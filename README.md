# HexEdit — 浏览器本地十六进制编辑器

在浏览器内本地编辑不超过 **8 MiB** 的二进制文件：十六字节一行的虚拟滚动十六进制表，
支持插入 / 删除 / 替换、多步撤销重做、Worker 后台搜索、快照式导出（含 SHA-256 摘要）。
零依赖、零构建，纯 ES 模块。

## 运行

```bash
npm run serve          # 或任意静态文件服务器，如 python3 -m http.server 8080
# 打开 http://localhost:8080
```

（必须通过 HTTP 访问：ES 模块与 module Worker 不支持 file:// 协议。）

## 测试

```bash
npm test               # node --test，41 个用例
```

## 架构

```
src/
  piece-table.js   编辑模型：片段表（范围引用原文件 + 追加区）
  editor.js        编辑器：撤销/重做、光标选区迁移、搜索状态、批量替换
  search-core.js   字节模式搜索（Boyer-Moore-Horspool），Worker 与测试共用
  search-worker.js 搜索 Worker（浏览器 self / Node worker_threads 双兼容）
  sha256.js        增量式 SHA-256
  exporter.js      快照式导出：逐段生成 + 流式摘要
  app.js           界面：虚拟滚动表格、键鼠交互、搜索/导出接线
test/              node:test 对拍测试（小数组参考实现 vs 片段表）
```

### 编辑模型：片段表（piece table）

文档是若干**段**的序列，每段 `{buf, start, len}` 引用两个只增不改的缓冲区之一：

- `ORIG`：原始文件字节，加载后永不修改；
- `ADD`：追加缓冲区，新字节只往尾部追加，已写入的字节永不改写（唯一例外见下）。

插入 / 删除 / 替换统一为 `splice(pos, delLen, ins)`：在 `pos` 与 `pos+delLen` 处拆分
段列表，丢弃中段、接上插入段，相邻同源连续段合并。**每次编辑只重组段数组
（O(段数)），绝不复制整份文件**；连续键入经合并后段数保持个位数。

两个受控优化：

- **半字节就地改写**：十六进制输入的第二个半字节补全时，若目标字节恰是 ADD 区
  最后写入的字节（刚由首半字节追加、没有任何撤销快照或进行中的导出引用它），
  则就地改写该字节，不产生新段。导出进行期间此优化被冻结（`freeze/unfreeze`），
  自动回退为普通 splice。
- **撤销合并**：相同 tag 的相邻编辑（一个字节的两个半字节、连续 ASCII 键入）
  并入同一撤销单元。

### 撤销 / 重做与修订号

段对象不可变、段数组整体替换，因此旧段数组天然是历史快照：撤销 = 换回旧段数组
（连同当时的光标与选区）。撤销后产生新编辑即清空重做栈（撤销分支）。每次内容
变化（含撤销/重做）递增 `revision`，作为搜索结果的版本依据。

### 光标与选区迁移

`mapPosition(p, pos, delLen, insLen, assoc)` 把任意文档偏移映射到编辑之后：
编辑点之前不动、之后平移、被删区间内收拢到插入内容末端；`assoc` 控制落在插入
点处时偏左（选区锚点）还是偏右（光标）。撤销/重做直接恢复当时保存的光标与选区。

### 搜索：Worker + 修订绑定

搜索时主线程对当前文档做一次性快照（8 MiB 复制约 10ms），连同修订号 `rev`
转移给 Worker；Worker 返回绑定该 `rev` 的命中位置。搜索期间若继续编辑，
`rev` 即与当前 `revision` 不符 → 结果标记**已过期**，「全部替换」禁用，
跳转下一个匹配会自动重新搜索。批量替换对未过期结果按从左到右不重叠选取、
从后往前应用（位置互不影响），整体为**一个撤销单元**。

### 导出：快照语义 + 流式摘要

导出开始时捕获段数组引用（不可变），随后逐段把缓冲区视图喂给增量 SHA-256
并推入 Blob 部件列表，按 4 MiB 粒度让出事件循环。**导出进行中的任何编辑都不
影响该份下载**：编辑只会换出新的段数组，旧段与底层字节保持不变；就地改写优化
在导出期间被冻结。完成后触发下载并展示十六进制摘要。

## 已知取舍

- 随机位置的大量小编辑会让段数缓慢增长（每编辑约 +2 段），单次编辑为 O(段数)；
  实测 8 MiB 文档上数千次随机编辑后单键延迟仍 < 1ms。若需支持超长编辑会话，
  可在此之上加「段表归一化」（把段改为直接引用缓冲区对象后即可安全压缩），
  当前为保持模型简单未引入。
- 撤销栈上限 1000 步；搜索快照为全量复制（8 MiB 约 10ms），未做增量同步。



## 掩码查找
masked.html 复核当前 PieceTable 修订的字节快照。模式每项两位十六进制或 ?（半字节通配），1..64字节；查询范围[start,end)完全包住匹配片段。Worker 接收有序 Uint8Array 分段，须找到跨任意分段的重叠命中，返回原快照绝对位置和实际匹配字节；至多limit个命中，另报告是否尚有命中被截断。空片段合法，空范围无命中；总快照至多1MiB，非法描述、边界或上限整次拒绝。结果携带查询及修订身份，输入变化立即失效，旧回复不覆盖新查询。原精确字节搜索和编辑功能保持可用。
